# 0004. 저장 암호화와 서비스 사이 좌표 봉투에 서로 다른 열쇠를 쓴다

## 맥락
일정·추천 본문에는 사용자가 어디를 다니는지가 좌표와 함께 들어 있다. 저장소 파일이나 백업이 빠져나가면 그대로 읽히고, 서비스 사이 요청 줄에 실린 좌표는 같은 망의 다른 컨테이너와 중간 기록에 드러난다.

## 선택지
1. 평문 그대로
2. 하나의 열쇠로 저장과 전송을 모두 감싼다
3. 저장 열쇠(이 서비스만)와 전송 열쇠(hub·agent 와 공유)를 나눈다

## 결정
3번. 저장은 `PayloadCipher`(AES-GCM, 자리마다 다른 AAD, 열쇠 여러 개로 교체), 전송은 `LocationSeal`(AES-GCM, AAD `map|loc|v1`, 만든 시각과 나이 상한). 좌표는 늘 봉투로만 오가며 평문 길은 없다. 열쇠가 없으면 기동하지 않는다.

## 결과
전송 열쇠를 가진 서비스 하나가 뚫려도 저장된 본문은 열리지 않는다. 대신 배포할 때 열쇠 두 종류를 만들어 넣어야 하고, 세 서비스가 전송 열쇠를 같은 값으로 가져야 한다.
