# 0001. 서빙과 마이그레이션을 다른 진입점·다른 역할로 나눈다

## 맥락
서빙 프로세스가 기동할 때 Flyway 를 돌리면 서빙 계정이 DDL 권한을 가져야 한다. 그러면 서빙이 뚫렸을 때 스키마까지 바꿀 수 있고, 여러 인스턴스가 동시에 떠서 마이그레이션이 겹칠 수 있다.

## 선택지
1. 서빙 기동 때 Flyway 실행(Spring Boot 기본)
2. 별도 마이그레이션 진입점 + 역할 분리(소유자·마이그레이터·런타임)
3. 외부 마이그레이션 도구만 사용

## 결정
2번. 서빙은 `spring.flyway.enabled=false` 이고 켜면 기동을 거부한다. 마이그레이션은 같은 이미지의 `map.migration.UserMigrationApplication` 이 `map_user_migrator` 로 붙어 `SET ROLE map_user_owner` 로 한다. 서빙은 `map_user_runtime` 으로만 붙고, 기동 때 자기 권한이 DML 뿐인지 확인한다. 빈 데이터베이스는 일회용 부트스트랩 진입점이 V001~V004 를 세운다.

## 결과
서빙이 뚫려도 스키마를 바꿀 수 없다. 대신 배포 순서가 늘었다(부트스트랩 → 마이그레이션 → 서빙). 통합 실행은 이 순서를 일회성 서비스로 돌린다. 마이그레이션 진입점에는 repair 가 없어 체크섬을 맞출 때는 Flyway 명령줄 도구를 쓴다.
