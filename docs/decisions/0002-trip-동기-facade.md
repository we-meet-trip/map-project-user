# 0002. 일정 생성에 동기 facade 를 둔다

## 맥락
추천은 agent 가 비동기로 만들고 결과는 스트림으로 온다. 앱이 접수 뒤 결과를 롱폴링하게 하면 앱의 상태 관리가 복잡해지고, 결과를 앱 형식(정류지·이동 카드·날씨)으로 접는 일을 앱이 해야 한다.

## 선택지
1. 앱이 `/recommend/{jobId}` 를 롱폴링
2. 서버가 요청 하나에서 완료까지 기다리는 동기 facade(`/trip/*`)

## 결정
둘 다 둔다. 앱의 일정 생성은 `/trip/generate`·`/route`·`/research`·`/replan` 동기 경로를 쓰고, 비동기 경로는 그대로 남긴다. facade 는 초안을 0.7초 간격으로 확인하며 기본 110초까지 기다린다.

## 결과
앱이 단순해지고 변환 규칙이 서버 한 곳(`TripMapping`)에 모였다. 대신 기다리는 동안 요청 스레드를 하나 쓰고, 대기 상한을 앱·앞단 프록시보다 짧게 맞춰야 한다([troubleshooting.md](../troubleshooting.md) T-TRIP-01).
